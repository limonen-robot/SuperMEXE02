# 実機のコードを使う仮想マイコン

## 目的と共通になるファイル

`G431KB_motor/main.cpp`、`G431KB_motor/feedback_controller.h`、`G431KB_sensor/main.cpp`を**変更せずにそのファイルから直接ビルド**します。PIDをMATLABへ書き直す構成ではありません。追加した自作の`.c/.cpp/.h/.hpp`も各ボードのフォルダー以下から読み込みます（mbed-osと生成物は除外）。`.c`はC11、`.cpp`はC++17です。実機用のC/C++間の`extern "C"`などはそのまま必要です。

仮想環境で制御コードを改良すると、編集対象は実機に書き込むソースそのものです。実機用のMbedプロジェクトと依存ライブラリは残しています。仮想環境用の`native/mbed.h`を実機プロジェクトへコピーしないでください。実機のターゲット用ビルド・書き込みは従来の手順です。

PC側も`motor_app/app.py`、`feedback_ui.py`、`feedback_model.py`、`sensor_stream.py`などの元ファイルを読み込みます。制御処理の複製は作っていません。`launch_pc.py`だけが、Serial APIをlocalhostへ切り替え、アプリの`time.monotonic()`を仮想マイコンの時刻へ切り替えます。標準ライブラリの時計は変更しません。実COMポートへの接続はこの起動モードでは拒否します。

## 信号の経路

Simulinkの圧・流量 → センサー感度とRC → 12bit仮ADC → **実sensorのmain.cpp** → 実際のASCIIのS/T行 → 元Pythonの計測・平均・変換表 → FBVAL等の実ASCII指令 → **実motorのmain.cppとヘッダー** → マイクロ秒予約のCW/CCW → パルス積算位置 → 位置―抵抗表 → 循環モデル。

motorのPA_0からのVCTは仮リレー（ON 5ms/OFF 3ms）を通り、sensor PB_0とSimulinkの空気圧装置に入ります。リレー遅れは未測定の仮値です。実機の4ADC・4軸・最大3PIDという制限も元のコードが判定します。4枝を同時に独立PID制御するには、実機側の資源・配線・ソフト変更を含めた設計が別途必要です。

## 必要な環境

- Windows x64、Python 3（Tkinterを含む）。この仮想接続は標準ライブラリだけで動き、pyserialのインストールは不要です。通常の実機接続用Pythonアプリには従来通りpyserialが必要です。
- Windows x64用LLVM-MinGWの`clang++.exe`。今回の動作確認は20261104 ucrt-x86_64版。MATLAB用MEXコンパイラは不要です。
- 循環リポジトリ側はMATLAB/Simulink。接続にはMATLABのtcpclientを使用。

## 起動

循環リポジトリの`firmware_in_loop/README_実機コード検証.md`を参照してください。直接起動する場合はPowerShellで以下を実行します。パスは自分の環境に合わせてください。

```powershell
& .\firmware_in_loop\start.ps1 -Python 'C:\path\python.exe' -Compiler 'C:\path\llvm-mingw\bin\clang++.exe'
```

元PCアプリが起動し、左右冠循環の設定例を表示します。勝手に制御は開始しません。例は左冠100・右冠60mL/minの一定目標です。生理的自己調節を検証した設定ではありません。

ソースを変えたら、シミュレーションを止めてから同じ起動操作を繰り返してください。前回このスクリプトが起動したプロセスを止め、再ビルドします。起動時はソースのSHA256も記録し、不一致のDLLは実行しません。生成したDLLやログは`build/`内でGit管理から除外します。

## 時間の扱い

接続前はGUIの接続・設定のため、保持したADC値で仮想マイコンの時計だけを進めます。**制御開始はSimulinkを実行してから**行ってください。接続後はSimulinkだけが時計を進めます。遅い計算や一時停止を通信断と誤認しないためです。終了時はSTOPを送り、時計を停止します。次の試行は仮想環境を再起動してください。

元mainの1msスリープ、Timeout、ADC100Hz、VCT後の取得時刻、原点復帰待機、PID周期・通信監視は仮想時計を使います。Timeoutはマイクロ秒単位のイベントとして実行します。main処理と割込みを交互に進め、C++ mainの途中でCPUを割り込ませる再現はしていません。

## 検証

```powershell
& 'C:\path\python.exe' .\firmware_in_loop\verify_native.py
```

変更していないC++によるREADY/PING、10パルスの移動、ADC送信、VCT同期、3PID制限、-130パルスのPID補正、FBデータ途絶停止を確認します。

`verify_pc.py`は元Tk画面を非表示で構築し、接続・設定転送・原点復帰・初期移動・センサー処理・FBVAL送信・PID状態まで確認します。別プロセスでサーバーを起動し、Simulinkを25秒以上実行する結合試験用です。通常の操作には`launch_pc.py`を使ってください。

通信・GPIOの証跡は`build/trace.jsonl`、アプリのエラーは`build/app_error.log`です。マイコン出力の位置表示は指令積算、Simulink抵抗に使う位置はGPIO立上がり積算です。

## 再現範囲の限界

- STM32命令、CPU実行時間、割込み優先度・処理負荷による遅延は未再現です。実コードの周期指定は検証できますが、実機の最悪実行時間・割込み競合の保証にはなりません。
- ASCII内容は実コードそのものですが、USB/UARTの電気波形・115200bpsの転送待ち・ドライバ遅延は未同定で、localhost通信は理想的な接続です。
- ADCは0～3.3V・12bitと仮定。感度・ゼロ点・入力雑音、ドライバの実入力しきい値・脱調・バックラッシュ・原点復帰精度は未同定です。現状のパルスは全て受理し、原点復帰1.02秒後に理想的に位置0へ戻します。
- ステップパルスのGPIOは再現しますが、PWM/DMA/I2Cなど未使用の周辺APIは実装していません。今後利用する場合は境界アダプターを追加します。コンパイルエラーを隠して代替動作にすることはありません。
- ソースの共有は、ハードウェアの再現精度や実機での動作保証とは別です。仮想環境での検証後も実機確認は必要です。
