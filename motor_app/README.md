# SuperMEXE02 V4 追加機能の使い方

## 最初に行うこと

1. アプリを閉じる。
2. D軸のZHOMEを使う前に、D側リレー入力をC側の共通線から分離し、motor用ボードのD5（PA_15）へ接続する。C側はA6（PA_7）のまま。A/Bは従来どおり。
3. VS Codeの「タスクの実行」→ **Mbed: G431KB_motor Flash** でmotor側を書き込む。
4. **App: Motor control** からアプリを起動し、motor側のCOMポートに接続する。

アプリとmotor側コードは両方V4が必要。sensor側マイコンは不要。
起動・接続だけでは自動で原点復帰や移動をしない。

## 設定ファイルの保存・読み込み

画面上部の **「設定を保存…」** を押すと、Windows標準の保存画面が開く。
保存場所とファイル名を選んで保存する。初回の保存先は次のフォルダーで、画面内で自由に移動できる。

```text
C:\Gitkraken\iwasaki_lab\SuperMEXE02\motion_settings
```

形式は **JSON（.json）**。2回目以降は直前に保存・読み込みしたフォルダーを初期表示する。同じファイル名への上書きは保存画面で確認する。

保存する内容：

- A〜Dの登録動作と順番（移動・待機・ZHOME、移動量、速度または時間）
- 周期、VCT幅、各軸の開始遅延
- 繰り返し、開始前ZHOME、通常実行時のVCT出力の設定
- 手動操作の軸と速度

時間は整数µs、移動量は整数パルスで保存するため、0.001 ms単位や1パルスの設定を保持する。
左側に入力しただけで一覧へ追加していない動作、COMポート、接続状態、ログ、実行途中の位置・進捗は保存しない。

**「設定を開く…」** で保存したJSONを選ぶと、現在の設定をファイルの内容に置き換える。
読み込みは設定の復元だけで、接続・移動・ZHOME・繰り返し実行を自動では開始しない。
編集中で往復が未完成の設定も保存できるが、実行時の合計移動量や速度・周期の検査は引き続き有効。
不正な形式や異なるパルス換算のファイルは読み込まず、現在の設定を維持する。
実行中・原点復帰待機中は保存と読み込みを無効にしている。

この機能の利用にマイコンの再書き込みは不要。アプリを再起動するとボタンが表示される。

## 動作の登録・実行

「動作の登録・実行」タブの左側で軸と「動作の種類」を選ぶ。

| 種類 | 入力 | 内容 |
|---|---|---|
| 移動 | CW/CCW、移動量[mm]、速度[mm/s]または時間[ms] | 現在位置からの相対移動 |
| 待機 | 「時間を指定」の欄にmsで入力 | パルスを出さずに指定時間待つ。速度・移動量の欄は使わない |
| ZHOME | 時間入力は不要 | 原点復帰信号20 ms → OFF → 1秒待機。時間は固定 |

「この動作を追加」で、その軸の一覧に追加する。各軸32件まで。
上へ・下へ・選択を削除で整理できる。「この動作だけ実行」は一覧を変更せず、左側の1動作を実行する。
「登録した動作を実行」は、登録内容と周期設定を先にマイコンへ送り、全応答確認後に開始する。
登録がある最大4軸を並行実行し、各軸は自分の登録順に動く。

## 周期・VCT・繰り返し

「周期・ZHOME・手動操作」タブで設定する。

- **周期[ms] / bpm**：相互に連動。600 ms = 100 bpm。
- **VCTパルス幅[ms]**：初期値30 ms。周期より短くする。
- **開始遅延[ms]**：共通開始時刻/VCTから、各軸を何ms遅らせるか。動作一覧内の待機とは別。
- **周期で繰り返す**：共通周期で各軸の動作を繰り返す。VCTはPA_0から自動出力。
- **最初にZHOME**：登録がある軸を最初に原点復帰させ、固定待機終了後にVCTと動作を開始。
- **通常実行でもVCTを出す**：1回だけの登録動作実行でもVCTを出す。全動作の終了時にVCTも止まる。
- **VCTだけ開始**：モーターを動かさずVCTを出す。「全停止」で終了。

繰り返しの検査：

1. 各軸の符号付き移動パルス数の合計が0であること。登録中から検査し、不一致なら実行不可。
2. 各軸の移動・待機時間の合計が周期以下であること。余った時間は次周期まで待機。
3. 繰り返し一覧にZHOMEを入れないこと。必要なら「最初にZHOME」を使う。
4. 各軸の最高速度の合計が20 mm/s以下であること。

開始遅延は周期を超えてもよい。例：周期600 ms、A開始遅延630 msなら、Aは最初のVCTから630 ms後に始まり、その後600 msごとに開始する。動作本体は600 ms以内に収める。

周期はPCから毎回指示せず、マイコンで「開始時刻＋周期×回数」の絶対時刻を基準に管理する。
±1 msを目標に設計しているが、実機の周期精度・最大負荷時の挙動は未測定。

### 最初の繰り返しテスト例

A軸に次を登録する。

1. 移動：CW 0.1 mm、時間100.000 ms
2. 待機：100.000 ms
3. 移動：CCW 0.1 mm、時間100.000 ms

周期600 ms、「周期で繰り返す」を選び、登録動作を実行する。
0.3秒で指令上の元位置へ戻り、残り0.3秒は待機する。PA_0には600 ms周期のVCTが出る。
必要に応じてB/C/Dにも往復動作を追加する。
「最初にZHOME」はリレー配線と原点位置を確認してから使う。

## スケール適用

「動作の登録・実行」で対象の軸タブを選び、「周期・ZHOME・手動操作」で新しい周期を入力し、スケール適用ボタンを押す。

- 移動量・方向・順番は維持。
- その軸の移動と待機の時間を、合計が新周期に収まるよう比例変更。
- 移動の指定方法は時間指定になる。速度も再計算して表示。
- ZHOMEの20 ms信号と1秒待機は固定で、短縮しない。
- 開始遅延は変更しない。
- 速度上限や時間分解能を超える場合は適用せず、エラーを表示。
- 時間は1 µs単位で計算する。スケール時の1 µs未満の端数は、次周期までの待機時間になる。

周期を入力しただけでは登録動作の時間は変わらない。スケール適用は各軸ごとに行う。

## 原点復帰ボタン

「周期・ZHOME・手動操作」の **A/B/C/D ZHOME** を押す。
対象軸へ20 ms信号を出し、OFF後に1秒待つ。READY/HOME-ENDの接続がないため、実際の復帰完了を検出しているわけではない。

| 軸 | ZHOME出力 |
|---|---|
| A | PB_4 / D12 |
| B | PB_5 / D11 |
| C | PA_7 / A6 |
| D | PA_15 / D5（分離配線が必要） |

D5とA5には基板上の接続関係があるため、A5も別信号には使用しない。

**ZHOME開始後の原点復帰そのものは、現在の配線ではアプリから中断できない。**
「全停止」で他の軸・VCT・後続動作を停止しても、原点復帰の固定待機が終わるまで次の操作は無効。
リレー信号は独立したタイマーでOFFになり、停止操作でONのまま残らないようにしている。

## 押している間の手動操作

「周期・ZHOME・手動操作」で、手動操作の軸・速度を指定し、CWまたはCCWを押し続ける。
離す、ウィンドウのフォーカスを失う、最小化する、通信が切れると停止する。
マイコン側でも手動継続通知が約0.5秒途絶えるとパルスを停止する。

手動操作はプログラム運転と同時には使えない。移動量の上限は使わないため、可動範囲を確認して操作する。
キーボードや自動反復ではなく、マウスの押下・解放で操作する。

## 時間と移動量の分解能

- 時間入力と表示はmsに統一し、小数3桁（0.001 ms = 1 µs）を扱う。例：100.001 ms。
- 移動量の最小指令は1パルス。実測換算2,500 pulse/mmより **0.0004 mm = 0.4 µm**。
- 移動量のスピンボックスは0.0004 mm刻み。1パルス未満は拒否し、それ以上の端数は整数パルスに丸めた指令値を表示する。
- 時間指定の移動は総時間を整数µsで転送し、各パルスのHigh/Low間隔に端数を分配する。総時間を一定パルス周期の倍数へ丸めない。
- 速度指定は従来どおり整数µsのパルス半周期に換算する。表示は換算後の速度・時間。
- 現在の20 mm/s上限では、1パルスの移動に最低0.020 ms必要。例：0.0004 mmを0.021 msで動かす指令は可能、0.019 msは速度超過で拒否する。
- 待機は最小0.001 ms。VCT周期は10 ms以上、VCT幅は1 ms以上の範囲内で0.001 ms刻みに設定できる。ZHOMEの20 ms信号＋1秒待機は固定。
- 入力分解能は実機の時間精度・機械的な位置精度を保証するものではない。割り込み遅延やドライバー・機構の応答があるため、実測は別途必要。

## 停止・上限・注意点

- 「全停止」はモーターの指令パルス、VCT、残り動作、繰り返しを停止。ZHOMEには上記の制約がある。
- 通信切断・異常後に自動再開はしない。再実行は現在位置から一覧の先頭に戻る。
- 通常の通信生存通知が約2秒途絶えると、マイコン側も停止処理を行う。
- `STOPPED TIMING` は処理が予定時刻に間に合わなかったことを示す。速度・同時軸数を減らして確認する。
- 1動作の移動量は6 mmまで。1軸20 mm/s、各軸の最高速度の合計20 mm/sまで。
- 待機は0.001〜600,000 ms、周期は10〜60,000 ms、開始遅延は0〜600,000 ms。
- 換算は実測済みの2,500 pulse/mm。戻り位置の検査も整数パルス数で行う。
- 実位置・機械端・累積移動範囲は検出しない。指令の移動合計0でも、実位置の復帰を保証するものではない。
- 加減速は未実装。パルス停止は非常停止装置やドライバー電源遮断を代替しない。
- アプリ終了後も使う登録一覧は、終了前に「設定を保存…」でファイルに保存する。

## 実装・確認内容

固定長の動作配列をマイコンに保持し、割り込み内ではパルスとタイマーの処理を行う。画面描画・設定計算・通信ログはPCで処理する。
V4のmotor側ビルドと、1パルス・1 µs単位の計算・転送順序・停止・ZHOME待機・繰り返し検査・手動操作など51件のアプリテストを実行済み。
ボードへの書き込み、モーターの実動作、VCTの実測は実行していない。
